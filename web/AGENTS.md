# AGENTS.md — `web/`

Rules for the React SPA. They extend the root [`AGENTS.md`](../AGENTS.md), whose
conventions apply here too: one paragraph per rule, and a `→` link to the decision
record you must read before changing the rule.

## Text and styling

- **Removing a presentational transform makes every transformed string a caller (#662).** `.badge`'s `text-transform: uppercase` hid two lower-case i18n strings. Removing it in #652 rendered `no entry` and `yes` as typos in all three locales until `web/src/i18n/badgeCase.test.ts` pinned them. Apply #394's caller rule to text: inspect every transformed string, not only the code that removed the transform.
- **Help prose naming a control follows that control's LABEL, per locale, and only review checks it (#688).** `catalogParity` compares key sets; renaming a control in translated prose passes every gate. In #678, `es` help called the expiry field *caducidad* and *vencimiento* while its label said `Vencimiento`; `tl` called it *pagkaluma*, meaning becoming obsolete. A guard requiring help strings to contain their label term was built and **rejected on evidence**. Of 81 pairs from help prose's `<strong>` spans, 12 failed in `es` and 20 in `tl` without a defect. Spanish number agreement and Tagalog affixation defeat the check. `Nabebenta` is not a substring of `naibibenta` or `maibebenta`; they share no common prefix, only the root `benta` behind different prefixes. Matching requires root extraction, not `includes()` or stem matching. Skipping `tl` would miss the locale where the defect landed. When writing help or glossary prose that names a control, look up its label **in each locale** and use its word. A locale must never disagree with itself about a control. **Nothing enforces this.** → [`688-i18n-help-label-pairing.md`](../docs/decisions/688-i18n-help-label-pairing.md)
- **Count a selector's call sites before styling it (#662).** Across #651/#652, `.stat`/`.stat-label` no longer existed; `.eyebrow` and `.toolbar` had zero call sites, but `.toolbar` was restyled anyway. Half of #651 changed nothing on screen, caught only when the owner compared before/after screenshots. Before styling an issue's selector, run `grep -rn "<class>" web/src --include='*.tsx'` and record the count in the design. Before DELETING one, grep the whole repo with `git grep -n "<class>" -- ':!web/src/styles.css'`. The Playwright harness under `tools/simulation/ui` also selects by class; its canary and capture specs run only on dispatch. A stale selector there surfaced weeks later on a release branch (#883, run 35136083182). `web/src/styles.harness-selectors.test.ts` now fails the unit suite on such selectors. Zero call sites is legitimate for deliberate groundwork, but record that decision before merge.
- **Retire a style-guard assertion only with the CSS rules it reads (#824).** The same change must name a successor guard or record a deliberate coverage reduction. MUI styles render through Emotion and never enter `styles.css`, so leaving an old postcss assertion in place after its selector disappears creates a green test with no subject. `styles.conversion.test.ts` compares every production `className` token, including MUI `slotProps`, with parsed CSS selectors and rejects unsupported dynamic producers; it deliberately does not detect unused CSS. `styles.csp.test.ts` also scans production TypeScript styling literals, while `farmTheme.policy.test.ts` and the narrow MUI source census own theme and source policy. → [`824-style-guard-conversion.md`](../docs/decisions/824-style-guard-conversion.md)

## Lint

- **`npm run lint` runs ESLint from its own install in `web/lint/`, and its suppressions file may only shrink.** Run `npm ci --prefix lint` once. typescript-eslint 8 declares `typescript <6.1.0` and needs the classic compiler API, which TypeScript 7 does not ship, so `web/lint/package.json` pins TypeScript 6 for the linter while the app builds with 7. `web/eslint.config.js` only re-exports `web/lint/eslint.config.js`, because ESLint 10 lints only files under the config's directory. The config enables `js` and typescript-eslint `recommended`, `react-hooks/rules-of-hooks`, `react-hooks/exhaustive-deps`, type-aware `@typescript-eslint/no-floating-promises`, and errors on unused disable comments. It turns off only style rules and `no-unused-vars`, which tsc already owns. Pre-existing violations live in `web/lint/eslint-suppressions.json`, counted per file and rule. A new violation fails, and so does a suppression that no longer matches: ESLint 10 exits 2 unless `--pass-on-unpruned-suppressions` is passed, which CI never does. ESLint never checks an entry whose file is gone, and it accepts any count the same PR writes, so CI also runs `web/lint/check-suppressions.mjs`. It rejects entries for missing files and, on a pull request (`--base <ref>`), any file/rule entry that is new or higher than at the base. The one exception is a rule that the base's own config did not apply to that file: the entry may then record at most the sites that rule finds in the file's BASE source. That is how a newly enabled rule, or a widened glob, records existing sites, while a moved or added file and any new site still have to be fixed. An unreadable `--base` exits 2 rather than skipping the check. Renaming a file that has suppressions therefore means fixing its violations. After fixing a suppressed violation, run `npm run lint -- --prune-suppressions` and commit the smaller file. Delete entries for deleted files by hand: `--prune-suppressions` leaves them. Never run `--suppress-all` or `--suppress-rule` to admit a new violation, and never fix an `exhaustive-deps` finding by auto-fix: a wrong dependency array can loop renders. CI's `web` job runs the lint; the pre-commit hook lints only staged `web/src` files.

## Data loading

- **A screen reads data through `useLatestLoad` or `usePagedList`, never through `await` or `.then(` inside a `useEffect` (#1185).** A raw async effect lets a response for inputs the user has already left land after the newer one and overwrite it, or clear its error, loading flag or rows. Review caught it on 23 PRs (#467, the #703 series, #918 then #940). `useLatestLoad(inputs, load)` in `src/components/` aborts the superseded run and drops its result and its error; `usePagedList` does the same for paged lists, and `useDialogAction` covers dialog writes. A `no-restricted-syntax` rule in `web/lint/eslint.config.js` fails an `await` or `.then(` inside a `useEffect` callback in `src/routes/**` and `src/components/**`. The sites that existed when it landed are in the suppressions file and move to the hook when their screen is next touched. It cannot see an async helper defined outside the effect, nor a write followed by a refresh in an event handler; only the hooks cover those.
