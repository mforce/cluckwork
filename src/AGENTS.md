# AGENTS.md — `src/`

Rules for the backend projects and their tests. They extend the root [`AGENTS.md`](../AGENTS.md), whose
conventions apply here too: one paragraph per rule, and a `→` link to the decision
record you must read before changing the rule. Persistence edits also read
[`Cluckwork.Infrastructure/Persistence/AGENTS.md`](Cluckwork.Infrastructure/Persistence/AGENTS.md).

## Conventions (follow these)

### Application shape

- **Result pattern:** domain/handlers return `Result` / `Result<T>` (see `Domain/Common`). Don't throw for expected failures; throw only for invariant violations such as `Flock.Create` guards.
- **Handler per feature**, invoked directly from endpoints — **no MediatR**. Register handlers/validators/repos in the owning module's file under `Cluckwork.Api/Modules/<Owner>/`; Access's go in `AddCluckworkIdentity` (#858).
- **Validation:** FluentValidation validators (`*Validator`), one per command; endpoints call `ValidateAsync` and return `ValidationProblem`.
- **Endpoints:** minimal APIs grouped under `/api/v1/...` via `Map<Feature>Endpoints`; writes require auth + an `Idempotency-Key` (middleware).
- **Nullable enabled**, no unused usings — both are build-breaking.
- **`.editorconfig` at `:warning` is a build error, and two C# style rules are gated that way (#985).** `EnforceCodeStyleInBuild` in `Directory.Build.props` runs the IDE analyzers during the build, and `TreatWarningsAsErrors` is already true there, so **any** rule written at `:warning` in `.editorconfig` fails the build repo-wide the moment it is committed — adding one is a decision, not a preference. Two are gated today: `csharp_using_directive_placement = outside_namespace` (IDE0065) and `csharp_style_namespace_declarations = file_scoped` (IDE0161). Fix a violation with `dotnet format style <project> --diagnostics IDE0065 IDE0161 --severity warn --include <file>`; do not hand-move headers. Measured, so you can rely on it rather than re-deriving it: those two are the ONLY rules this property activates at warning severity, because 116 of the SDK's 121 code-style diagnostics default to `Hidden`, four to `Info`, and the repo carries no `.globalconfig`, ruleset, `AnalysisLevel`, `AnalysisMode` or `dotnet_diagnostic.*` entry. Two exemptions, each for a reason that is not "this file is awkward": `SeamSurfaceTests.cs` and `TableOwnerTests.cs` keep inside-namespace usings because 25 of them are relative aliases resolving against the enclosing namespace, and the EF migrations tree keeps block-scoped namespaces because `dotnet ef migrations add` scaffolds them, so the exemption has to keep working for migrations nobody has written yet. **Both placements can shadow**: a using inside a namespace resolves relative to it and can bind to a sibling, and a using outside can be shadowed by a sibling namespace segment of the same simple name. The second is real here — a test namespace named `FlockScope` shadowed the production `FlockScope` class and produced 13 errors across six files — so never introduce a namespace segment whose simple name is also a type. → [`985-csharp-style-gate.md`](../docs/decisions/985-csharp-style-gate.md)
- **Declare cross-module references in the module ledger (#514/#842).** Nine namespace owners (Access, Farm, FlockManagement, EggOperations, Commerce, GeneralInventory, Finance, Insights and Platform) each have one file, `src/Cluckwork.Domain/Common/Architecture/Modules/<Owner>.cs`, with an `internal static class <Owner>ModuleRules { }` carrying the `[ModuleOwner]` row and the owner's outgoing `[ModuleEdge]` cells (`From`, `To`, `Kind`, `Reason`), each listing the top-level types realising it. File a cell with its `From` owner; a cell on another owner's class fails. The tests read them through `RealModuleLedger.Owners` and `Edges` (#859). `ModuleLedgerRealTreeTests` walks every `.cs` under `src/` and binds module-owned files: an edge is a type a node binds to, or the type declaring the member it binds to, so member access counts and an unused `using` does not (#1071). Undeclared edges, stale rows, unowned namespaces, parse errors, compile errors in module-owned files and file counts below the floor fail. An undeclared edge prints the `[ModuleEdge]` row to add and the file it goes in; read the code and extend the cell, never widen a reason. Key by owner and top-level type, never namespace or `file:line` (#632). `Customer.cs` under `Domain/Modules/Commerce/Sales/` is not an edge because both ends are Commerce. Each module's `[ModuleOwner]` row claims its fixed roots, `Cluckwork.{Domain,Application,Infrastructure}.Modules.<Owner>` (#1087), so a new feature folder needs no row; any other namespace, such as a leftover `Cluckwork.Application.Features.*`, is unowned and fails. **Platform is the free hub**: `Cluckwork.Api.*` (the endpoints under `Api/Modules/<Owner>/` included: they stay Platform-owned adapters), `Infrastructure.*` outside `Infrastructure.Modules`, `Domain.Common`, `Domain.Auditing` and `Application.Common` may reference anything and be referenced by anything. Narrowing this is Track B (#845–#847). Only review checks `Kind`: `W` writes through the other owner in one transaction; `R` reads or validates. The ledger authorises no move; the design's status line still governs. → [`514-module-ledger.md`](../docs/decisions/514-module-ledger.md)
- **The module-edge analyzer reports the ledger's three source failures while you edit and build; the tests stay the authority (#859).** `src/Cluckwork.Analyzers` runs in Domain, Application, Infrastructure and Api through an analyzer-only `ProjectReference`, and reads the rows from Domain's attributes, so an edited row applies without rebuilding it. It ports `ModuleLedgerScanner`'s semantic walk (#1071): CW1001 is an undeclared edge, at the reference, with the row to paste; CW1002 is a stale symbol; CW1003 is an unowned namespace; CW1000 means the compilation read no map. CW1002 is a compilation-end diagnostic, so an IDE shows it only with full-solution analysis, and a symbol that exists in no assembly is reported only by the Api compilation. It is developer feedback. `ModuleLedgerRealTreeTests` remains the CI authority and never calls the analyzer, and nothing stops `#pragma`, `NoWarn` or `.editorconfig` from silencing a CW id, so fix the row instead. Registry validation, the global-using rule and the file floor stay test-only. The central `Microsoft.CodeAnalysis.CSharp` pin is the analyzer's Roslyn and stays at the oldest compiler in use, 5.0.0 for SDK 10.0.1xx: a newer pin fails every build on that band with CS9057. A new module project adds the same reference. → [`859-typed-rule-registries.md`](../docs/decisions/859-typed-rule-registries.md#the-module-edge-analyzer)
- **No persistence type crosses an Application seam (#514/#847).** Public interfaces anywhere in `Cluckwork.Application` may not reach `DbContext`, `DbSet<>`, `IQueryable`, any `Microsoft.EntityFrameworkCore` type, the bases `Entity`/`AggregateRoot` as declared types, or any `Cluckwork.Infrastructure` type. This covers parameters, return types, generic arguments and properties of returned `Cluckwork.*` types. `SeamSurfaceRealAssemblyTests` reflects over every such interface and fails closed below 30. A second assertion forbids Application assembly references to EF, Npgsql or Infrastructure, keeping the first from being vacuous. Return a DTO, value object, concrete aggregate or `PagedResult`. → [`847-seam-surface-guard.md`](../docs/decisions/847-seam-surface-guard.md)

- **Every adapter declares its module reach, and shrinking it is required (#514/#846/#1073).** `AdapterReachRealTreeTests` walks every method and declared constructor in the ledger's endpoint, CLI and job namespaces and its two seeder types, including private helpers and primary constructors. It also walks direct route handlers in ledger-selected top-level programs. `RealModuleLedger.Adapters` records each non-empty owner set by enclosing type and member name. Top-level handlers use project, Program, mapping method and route, including literal HTTP method lists and named handlers. A new owner fails with the crossing type, `file:line` and a generated C# row. Platform is the free hub. This is not a multi-module ban, but each row must equal live reach: an unused owner, or a row whose adapter reaches nothing or no longer exists, fails and names what to remove. An `[AsParameters]` parameter fails because the walk reads no property types. **Endpoints, including top-level Program route handlers, forbid `AppDbContext`, `DbContext`, `DbSet` and `IQueryable` parameters or service resolutions regardless of the ledger**. CLI verbs, jobs and seeders may hold these types without counting them as reach. The walk reads parameter types, including typed lambda, local-function and anonymous-method parameters, and generic or `typeof` service resolutions from one API table. It shares the module ledger's owner resolution, fails on parse or registry errors and enforces a 40-adapter floor. It over-approximates adapters, cannot bind every simple name or infer transitive reach, and gains #843's adapter tiers on top. → [`846-adapter-reach-ratchet.md`](../docs/decisions/846-adapter-reach-ratchet.md)

- **Declare a tier's otherwise-unavailable module privilege before its surface exists (#514/#843).** `RealModuleLedger.AdapterTiers` names a namespace, closed-set `Privilege` (`DirectRepository` today), closed-set `Surface` (`MapMcp` today), and `ReviewBy` issue giving the exemption an end date. Both closed sets come from `AdapterTier.KnownSurfaces`, which the scanner also walks. `AdapterTierScanner` fails on a `[McpServerToolType]`-attributed type outside every declared tier namespace or a mapped surface (`MapMcp`) without a tier row, printing the C# row to add. A row with an unmapped surface and no type in its namespace is `Dormant`: informational and green because it precedes the code. The `Cluckwork.Api.Mcp` row (#806) is dormant while its surface is unmapped and its namespace has no type. `AdapterTierRealTreeTests.McpTierRow_IsDormantToday` asserts that row is dormant, so adding a tool type under that namespace or mapping `MapMcp` turns CI red. Drop that assertion in the same commit that activates the tier. Each tier also joins the reach guard's namespace roots and persistence-forbidden set. Tool-class repository parameters still need a `RealModuleLedger.Adapters` row; an `AppDbContext` parameter still fails. → [`843-adapter-tiers.md`](../docs/decisions/843-adapter-tiers.md)

- **The coupling matrix is generated from the ledger and its three walks (#848).** `CouplingMatrixRealTreeTests` validates the module-edge, EF-model and adapter reports before rendering `tests/Cluckwork.Application.Tests/Architecture/Data/coupling-matrix.md`, then compares normalized line endings with the committed file. Regenerate with `CLUCKWORK_REGENERATE_MATRIX=1 dotnet test tests/Cluckwork.Application.Tests --filter FullyQualifiedName~CouplingMatrixRealTreeTests`; do not hand-edit the Markdown. `docs/architecture.md` groups the modules by responsibility without arrows and links here for the edges; `RealTree_FeatureModuleDiagramNamesExactlyTheLedgerOwners` fails when that diagram names a different set of owners than the ledger. Its observable-differences table has seven `W`/`R`/dash mismatches with §3.4. A separate table records its unobservable `E`, `Q` and Platform cells. `P` is the free Platform hub, and `A` counts adapter reaches. → [`848-generated-coupling-matrix.md`](../docs/decisions/848-generated-coupling-matrix.md)

- **Adapters reach a contracted module only through the types its ledger row lists (#514/#849).** A module contract is one `I<Module>Module` interface, implemented by a `<Module>Module` that delegates to the existing handlers and repositories and is registered beside them. Every contract type sits top-level in its own file in the module's `Modules/<Owner>/Contracts/` folder and namespace (#1087): the interface, its commands and its `*Details` result records, and in Domain the enums entities use. `RealModuleLedger` collects them into the owner's `Contract`; nested types stay outside it, and a `Contracts` namespace naming no owner fails. `NamespaceFolderAgreementTests` keeps every file's namespace equal to its folder, so a file moved out of `Contracts/` cannot keep its contract namespace. `AdapterReachRealTreeTests` fails on an adapter parameter or service resolution that reaches the owner through any other type. It also fails on a listed type that is not declared or not owned by that module. `ModuleContractRealAssemblyTests` rejects any persistence type, entity or aggregate inside a contract type at any depth. That rule is stricter than #847, which allows concrete aggregates on other seams. Endpoints still call `IValidator<TCommand>` because commands are contract types. Finance, Farm, Flock Management, General Inventory, Egg Operations, Commerce and Insights are contracted today. `IInsightsModule` inherits `IReportQueries` and `IExportQueries`; never move either into `Contracts/`, because doing so lets any adapter or peer inject it past the ledger guards and skip the facade. → [`849-module-contract.md`](../docs/decisions/849-module-contract.md) **Peer modules reach a contracted module only through its contract or `seam` (#1023).** `PeerContractRealTreeTests` runs the adapter walk over every module's own namespaces and fails when a member takes another contracted module's type listed in neither its `Contract` nor its `Seam`. Adapters never get the seam. Farm's seam is `IAccountRepository`, `Account` and `UserRoleAssignment`; add to it only on purpose. Every `contract` and `seam` entry names a top-level, non-generic type, because the walk drops generic arity. Like the adapter check, it reads parameter types and service resolutions, never return types or method bodies. → [`1023-peer-contract-guard.md`](../docs/decisions/1023-peer-contract-guard.md) **Farm's contract stops at settings, logo and banner (#851), plus the cross-farm `IFarmDirectory` (#858).** `IFarmDirectory` ignores the tenant filter so the operator verbs and the lock sweep can list farms and resolve a farm code; `FarmDirectoryCallerTests` fails when a file outside `Api/Cli`, `Infrastructure/Jobs` and the directory's declaration, implementation and registration names it or `AccountRepository`, because a request path that reached it could show one farm another's. Sign-in resolves its farm code through `IIdentityProvider.ResolveFarmCodeAsync`, never `IFarmModule`, because that lookup establishes identity before `TenantContext` exists. That method is the only caller of the seam's cross-farm `IAccountRepository.FindBySlugAsync`; `FindBySlugCallerTests` fails when any other member references it (#1053). `FarmClock` stays on `IAccountRepository` because it sits in the Platform hub. Peer modules keep calling `IAccountRepository` and `Domain.Accounts` directly, the #162 locked currency snapshot included; do not fold that seam into the contract. → [`851-farm-contract.md`](../docs/decisions/851-farm-contract.md) **Flock Management has three contract interfaces (#852).** Adapters call `IFlockModule`; peer modules call the `IFlockLookup` read port and the `IMortalityLedger` write port, so a peer request does not construct six lifecycle handlers it never uses. `IMortalityLedger.AppendAsync` adds the movement to the caller's unit of work and never saves; keep it that way, because `MortalityLedgerAtomicityTests` is all that holds Submit's mortality in the entry's commit. `IFlockLookup.ResolveByNameAsync` returns `Ambiguous` with every candidate on a duplicate name, never a first match. ### Data and correctness

- **Every mapped table has one owner, derived from its entity's namespace (#514/#845/#1074).** `TableOwnerRealModelTests` walks the EF model and gives each table the module owner of its entities' CLR namespace: the longest owner prefix, treating exact claims as subtree claims. Platform never derives: a table whose entity resolves to a Platform namespace fails until a reasoned `RealModuleLedger.TableOwnerOverrides` row (table, owner, reason) assigns it. Those rows are the only hand-written ownership: the Platform tables and design exceptions. A table with no namespace owner, entities resolving to different owners, a stale, duplicate, unknown-owner or redundant override, undeclared or stale cross-owner foreign keys checked by constraint name and direction, and a walk below 30 distinct tables fail. A move into a Platform namespace, including a new unclaimed `Cluckwork.Domain.*` namespace, fails here. A move between modules changes the owner. This guard catches it only through a cross-owner FK row. `ModuleLedgerRealTreeTests` catches references left in the old module, and `CompatibilityExceptionRealTreeTests` catches outside reads when the new owner has a contract. A move with none of these passes as a deliberate module move. FKs touching Platform are untracked, and Insights owns no tables. This enforces ownership only: no schema change, configuration move or permission to write another owner's data. → [`845-table-owners.md`](../docs/decisions/845-table-owners.md)

- **Business dates, row timestamps and list sequences are separate facts (#819).** Keep farm operational dates as `DateOnly`. Every mapped business record except `AuditEvent` has PostgreSQL-stamped `DateTimeOffset CreatedAtUtc`. Records supporting in-place updates also have `DateTimeOffset UpdatedAtUtc`, equal to creation time on insert and replaced on each update. Factories and handlers never stamp these generic fields. Chronological lists order by business date, `CreatedAtUtc`, then a shadow per-table `bigint GENERATED ALWAYS AS IDENTITY` `Sequence`, all in the list's direction. Omit the business-date key when absent. `Sequence` resolves timestamp ties for a fixed dataset; it does not repair clock rollback or make offset pagination snapshot-stable across concurrent inserts. Give it a database uniqueness constraint. Never expose it through domain objects, responses, exports or screens. Name-ordered lookups and canonical FIFO or `FOR UPDATE` ordering do not gain a sequence. Classify every new mapped table through `ICreatedRecord`, `IMutableRecord` or an explicit framework or infrastructure exclusion. Each module declares its chronological types and exclusions beside its persistence configuration; `BusinessRecordModel` merges the contributions before its centralized model walk. Add a type to the module's chronological contribution only when users page or read it by time. `BusinessRecordModelTests` makes the choice explicit (#1024): every mapped `ICreatedRecord` sits in exactly one of `ChronologicalListTypes` and `NotReadByTimeTypes` (with a reason), so an undeclared timestamped record fails, and an owned entity type implementing `ICreatedRecord` is rejected outright because the census configures no timestamps or `Sequence` for owned types. It cannot tell whether a declaration is true; a time-paged record declared not-read-by-time passes, and only review of its reason catches that. Preserve action-specific timestamps and `Version`. Legacy audit backfills use only exact whitelisted row events, falling back to the documented unknown sentinel. → [`819-business-record-chronology.md`](../docs/decisions/819-business-record-chronology.md)

- **Every aggregate mutation must bump `Version`.** `Version` is an EF concurrency token (`IsConcurrencyToken`). EF puts the *original* value in the UPDATE's `WHERE` but never increments it. Without `Version++`, both concurrent writers match `WHERE Version = N`, so one silently overwrites the other instead of returning 409. This shipped three times; every fix and new mutation requires a parallel-race integration test.
- **Multi-tenancy:** every tenant-owned entity has `AccountId`, enforced by an EF **global query filter** and **`TenantStampInterceptor`**, which stamps inserts and rejects mismatched updates/deletes. `TenantContext` resolves per request from the JWT `account_id` claim. It is **single-assignment**: a differing re-resolve throws. At startup it is unresolved, so seeders use `IgnoreQueryFilters()`. Several farms share one deployment; sign-in takes a farm code, and one email address can belong to users in multiple farms. **`AccountId` is also an EF concurrency token on every entity carrying it (#562).** Database `UPDATE`/`DELETE` statements include `AccountId = <original>`, so a detached stub targeting another farm matches nothing. The interceptor alone cannot see a detached write; an owned-only edit on an attached stub wrote through before this token. The model walk in `AppDbContext.OnModelCreating` covers new entities automatically. Never remove the token. Database refusals under a resolved tenant log `Tenant.WriteRefusedByDatabase`. **`AccountId` must be a non-nullable `Guid`; both layers fail closed otherwise (#673).** The walk throws `TenantAccountIdShapeException` at model build for any other CLR type. The interceptor throws it at `SaveChanges` for a mapped type other than `Guid` or a value that does not box to one. Previously, a `Guid?` or strongly-typed id received neither token nor check, reopening #562's detached-write hole with every test green. Map new tenant-owned entities' `AccountId` as a plain `Guid`; a strongly-typed id requires reopening this decision, not a cast. **Identity's `AspNetUserRoles` has a shadow `AccountId` and composite foreign key to `AspNetUsers(Id, AccountId)` (#670).** Both layers select by property NAME, so the shadow column is stamped, verified and tokened. The FK refuses role grants to another farm's user or under no resolved tenant. The other four user-keyed Identity tables have no writer in `src/` and remain an accepted risk. → [`530-multi-farm-tenancy.md`](../docs/decisions/530-multi-farm-tenancy.md)
- **A farm code changes only through `Account.Rename`, reached by the `rename-account` verb (#732).** No endpoint, no Settings field, and never a raw `UPDATE`. The former hand-guarded `UPDATE "Accounts"` bumped `Version` manually, wrote no audit row and checked neither the slug pattern nor the reserved set. `Rename` uses provisioning's `TryValidateSlug` and bumps `Version` on a real change, **not** a no-op. Renaming to the existing code mutates nothing, preserving "every mutation bumps `Version`" without breaking an open Farm Settings form. The service resolves the code to an id, resolves the tenant, takes the tenant-keyed `FOR UPDATE`, then **compares both the locked slug and `Version` against the lookup snapshot**. Lookup and lock are separate statements; without this comparison, an intervening committed write could be silently overwritten. Both checks matter. `Version` catches ABA, a rename away and back that leaves the code unchanged. Comparing the slug catches a code change that did not advance `Version`, such as raw `UPDATE`. The accepted cost is that a rename racing a Farm Settings save or suspend also returns `Account.SlugStale`. `IX_Accounts_Slug` and the `DbUpdateException` catch govern destination-code uniqueness; the pre-read is convenience only. There is **no retired-code list**. Retired codes are immediately reusable, so `--slug <retired>` targets whoever holds one now. This accepted cost is why the verb and runbook require `list-accounts` immediately first. → [`732-farm-code-rename.md`](../docs/decisions/732-farm-code-rename.md)
- **Flock-scoped EF reads are discovered from the model (#613).** Every mapped `Flock` or entity with scalar `FlockId` must keep one structural `AccountId AND flock-scope` query filter. Only `UserRoleAssignment` is excluded because its rows resolve the scope. Two children without `FlockId` use parent/policy gates. Daily-entry list/detail loads `DailyEntryGrade` only through filtered `DailyEntry`; Worker-readable production totals correlate through that same parent. The lot movement ledger gates `EggInventoryMovement` through filtered `EggLot`. Both children's direct exports remain `AdminOnly`. Any new exclusion or parent-derived child needs an explicit rationale and causal mutation test. Do not replace the model walk with a recalled entity list or expression `ToString()` checks.
- **Flock-scoped writes require a resolved actor (#787).** `FlockScopeGuard` returns `Auth.Unauthorized` before reading assignments when `ICurrentUser` is unresolved. HTTP middleware resolves the actor; a non-HTTP caller must resolve a real user or deliberately declare a system actor. This rule covers writes only: an unresolved `FlockScope` remains unrestricted for EF reads. A resolved system actor has no assignment rows and is therefore account-wide, so adding a system-actor caller of a flock-scoped handler requires an explicit access review.
- **Transient-DB retry stops at unreplayable work (#269).** Use `EnableRetryOnFailure` only for self-contained EF units. Above a stateful detector (a counter, CAS stamp, or single-use claim), an automatic replay cannot distinguish the request racing itself from the signal the detector should catch. Use `SingleAttemptExecution` when replay is observable. When replay writes nothing, probe durability with a self-minted token. Choosing the wrong cure ships the bug. → [`269-transient-db-retry-boundary.md`](../docs/decisions/269-transient-db-retry-boundary.md)
- **`AuditEvents` carries a durable, GLOBAL monotonic ordering key (#508).** `Sequence` is a `bigint GENERATED ALWAYS AS IDENTITY` column mapped as an EF **shadow property**, reaching no API response, export or screen. It breaks ties in all five relevant order clauses: `ListAsync` and `created`/`creator`/`latest`/`promoted` in `GetProvenanceChunkAsync`. Previously, ties used `Id`, a random v4 Guid from `AuditWriter`, so same-microsecond changes could name the wrong actor as last changer. The counter is **one per table, not per account**. Values interleave across farms; it is never a per-farm revision number. Ordering still leads with `OccurredAtUtc`, so **clock rollback is unhandled**: a later insert stamped earlier sorts earlier without consulting `Sequence`. Pre-migration rows have **no recoverable write order**; the backfill used `row_number()` over the same random Guid for timestamp ties. → `docs/plans/508-audit-monotonic-order/01-diagnosis.md`
- **Suspension is immediate for *use*, not for *issuance* (#579).** Login checks `Account.IsActive`, then mints. A suspension committed between those steps returns 200 with an inert credential. The `FOR SHARE` lock that would close this window was declined twice for hot-path cost. #530's "race-safe" means use, not issuance. Inertness requires four premises: a live middleware read, `RefreshAsync`'s suspended check, suspension's same-transaction revocation of credentials existing when the sweep executes, and reactivation's revoke. Each has a guard that fails when that premise alone breaks. Breaking any one reopens #579. → [`579-suspension-issuance-window.md`](../docs/decisions/579-suspension-issuance-window.md)

### Auth and credentials

- **Farm configuration and identity are Owner-only (#729).** `GET` and `PUT /account/settings` and the logo and banner mutations require `OwnerOnly`; a Manager handles farm operations but cannot change the farm name, localization, sale-allocation policy, palette, logo, or banner. Keep `GET /account`, `GET /account/logo`, and `GET /account/banner` open to every authenticated role because the SPA shell needs those values. The Farm settings navigation entry follows the exact `Admin` role, while the rest of Setup keeps its `isAdmin` gate. → [`729-owner-only-farm-configuration.md`](../docs/decisions/729-owner-only-farm-configuration.md)

- **Auth:** asymmetric JWTs with rotating refresh tokens. Config stores PEM keys with escaped `\n`; call `PemKey.Normalize` before `ImportFromPem`. Integration tests generate an ephemeral RSA pair at process startup (`TestJwtKeys` in `CluckworkWebApplicationFactory.cs`). Never commit real key material.
- **Both JWT keys are checked at boot, and the check is serving-only (#510/#347).** `AddCluckworkIdentity` requires both keys non-blank **and importable**; use `IsNullOrWhiteSpace`, never `??` (the shipped `appsettings.json` carries `""`, which `??` does not catch), and import at boot rather than inside the `AddJwtBearer` delegate (which makes a corrupt key a per-request 500 behind a green health check). → [`510-jwt-key-boot-check.md`](../docs/decisions/510-jwt-key-boot-check.md)
- **Credential epoch revocation (#364).** Every access/refresh token is bound to the user's `CredentialEpoch` and every password-reset path bumps it. Epoch `0` is permanently retired, a missing or malformed claim is **always** a mismatch, and `CredentialEpochMiddleware` does a fresh DB read per authenticated request through `ICredentialEpochVerifier` (#857) — the round trip *is* the fail-closed guarantee, so do not cache it. The mismatch holds whatever the database holds (#1031): `CK_AspNetUsers_CredentialEpoch` makes a stored epoch below 1 unwritable, and login, the verifier and refresh each refuse one anyway. Never repair a bad row by setting it to 1; that revives outstanding epoch-1 credentials. **Break it and a revoked credential keeps working.** → [`364-credential-epoch-revocation.md`](../docs/decisions/364-credential-epoch-revocation.md)
- **First-run admin: `bootstrap-admin` (#283).** Creates an Owner with a generated password (stdout only, never the logger/OTLP) and `MustChangePassword=true`, **only** if the default account has no Owner; a re-run is a silent no-op. While the flag is set, `MustChangePasswordMiddleware` 403s everything except `auth/change-password` and `auth/logout`. → [`283-first-run-admin-provisioning.md`](../docs/decisions/283-first-run-admin-provisioning.md)
- **Break-glass: `recover-admin` (#265).** Same run-then-exit shape as `seed`, but deliberately **not** environment-gated — it must work against a real Production database. One transaction: freshly generated temp password (never one passed on the command line), rotated security stamp, every refresh token revoked, and a `User.BreakGlassReset` audit row carrying `--reason`. → [`265-break-glass-recovery.md`](../docs/decisions/265-break-glass-recovery.md) · [runbook](../docs/runbooks/break-glass-account-recovery.md)
- **Nothing writes an audit event without an actor (#500).** `AuditWriter` throws on an unresolved `ICurrentUser`; system callers declare a `SystemActors` identity and both seeders require an Owner. `ICurrentUser` is an **authorization input, not a label** — `FlockScopeGuard` reads its roles, so an actor built from a literal rather than `UserManager.GetRolesAsync` can fail an entire seed. → [`500-audit-actor.md`](../docs/decisions/500-audit-actor.md)

### Boot guards and process roles

- **Process role, not statement order (#347).** Declare a boot guard's scope. `ProcessRoles.From(args)` computes `Serving | OneShot` once before host construction, and every role-scoped guard takes it. Positional gating caused #331: validation during service registration killed `recover-admin` with SIGABRT 134. **Scope the whole subsystem, not only the setting that failed.** Add every serving-only guard to `ProcessRoleGuardTests.ServingOnlyGuards`, one row per *violation*, not per subsystem. → [`347-process-role.md`](../docs/decisions/347-process-role.md)
- **Proxy-trust boot guard (#260).** HSTS (#144) and the per-IP login limiter (#143) only work if the app trusts the proxy's `X-Forwarded-*`, which it does only for networks in `RateLimiting:TrustedProxies` — so an empty list in Production fails the boot rather than running with inert HSTS and a one-bucket limiter. Opt out with `RateLimiting:AllowNoTrustedProxies=true` only for a direct-TLS deploy with no fronting proxy. → [`260-proxy-trust.md`](../docs/decisions/260-proxy-trust.md)
- **Production Postgres TLS floor (#261/#262).** In Production the effective `sslmode` is a fail-closed allow-list: `VerifyCA`/`VerifyFull` silent, `Require` warns, **everything else — including unset — fails the boot**. `Database:AllowInsecureConnection=true` is the explicit opt-out for the co-located plaintext compose stack. When mapping a libpq param, a missing keyword usually means it is spelled differently in Npgsql (`keepalives`→`Tcp Keepalive`), not that it is unmappable. → [`261-postgres-tls-floor.md`](../docs/decisions/261-postgres-tls-floor.md)
- **GSS/Kerberos negotiation off by default (#332).** `PostgresConnectionString` appends `GSS Encryption Mode=Disable` unless the operator set it (detected by **presence, not value**), textually, after the TLS floor runs — a round-trip through the Npgsql builder would reorder the operator's string and throw on any keyword this version does not know. → [`332-gss-kerberos.md`](../docs/decisions/332-gss-kerberos.md)
- **Farm timezone + tzdata/ICU (#264).** A farm may be given its IANA zone at provisioning time with `provision-account --timezone` (#603, validated there against `FarmSettingsRules.IsKnownTimeZone` — the same rule Settings enforces, so the two cannot disagree); omitted, it starts in `UTC` and its Owner sets the zone in Settings after first login. The clock resolves zones via `TimeZoneInfo.FindSystemTimeZoneById` and fails closed, so the runtime image **must** carry tzdata + ICU — never an Alpine/chiseled base, never `InvariantGlobalization=true`. `TimeZoneAvailability.EnsureResolvable` asserts a canary at boot for **both** process roles. → [`264-farm-timezone.md`](../docs/decisions/264-farm-timezone.md)
- **A new Production boot guard must be taught to the sim harness (#370).** Every guard that fails the boot on missing config, and every config-key add/rename/retire, updates `tools/simulation/bootstrap.sh`, `docker-compose.sim.yml` and `verify-harness.sh` **in the same PR**, because that harness runs Production config on purpose. `e2e-smoke.yml` boots it on every PR touching `src/**`, `web/**`, `tools/simulation/**` or `deploy/**`, so a harness left behind usually fails there. A PR outside that workflow's path filter gets no signal, and `k6-baseline.yml` is `workflow_dispatch` only. Satisfy guards properly, never by disabling one. → [`370-sim-harness-boot-guards.md`](../docs/decisions/370-sim-harness-boot-guards.md)
- **A new required config key must also be taught to the AppHost (#565).** Aspire wires the API's configuration by hand, through `WithReference(database, connectionName: "Default")` and the `SharedState__Redis__ConnectionString` entry in `src/Cluckwork.AppHost/Program.cs`. A newly required key that nothing there supplies breaks `aspire run`. `AppHostModelTests` runs as `ci.yml`'s `apphost` leg and pins the entries the AppHost declares, but nothing derives the API's required-key set, so a new key is invisible until someone runs `aspire run`. Same PR, same discipline; the difference is only that #370's harness runs Production config while this one runs Development. → [`565-aspire-local-orchestration.md`](../docs/decisions/565-aspire-local-orchestration.md)

### Operations and callers

- **Migrate command + prod migration split (#263).** `dotnet Cluckwork.Api.dll migrate` applies migrations then exits — the pre-deploy-job entrypoint. Production sets `Database:MigrateOnStartup=false`, so the serving process never runs DDL; the guarantee is **ordering**, and `DatabaseReadyHealthCheck` is the backstop (`/health/ready` 503s while any migration is pending). → [`263-migrate-command.md`](../docs/decisions/263-migrate-command.md)
- **Container health probe: the `healthcheck` verb (#266).** Before host build and without DI, DB, or config, it GETs `/health/ready` over loopback and exits `0` only for 2xx. The hardened image has no curl/wget, and the probe must never report a false green. → [`266-container-health-probe.md`](../docs/decisions/266-container-health-probe.md)
- **Seed / simulation data is never boot-seeded (#280, #284, #279).** Run `ASPNETCORE_ENVIRONMENT=Development dotnet Cluckwork.Api.dll seed --profile demo|simulation` explicitly against an already-base-seeded, non-Production database. An unset environment defaults to Production and is blocked. The verb migrates, seeds and exits; it is authoritative and fail-loud. Both profiles require an Owner (#500). `simulation` also requires `Simulation:CastPassword` and fails closed without it. **`demo` accepts `--farm-code <slug>`** to seed that farm instead of the default. It resolves by slug like the account lifecycle verbs; an unknown code exits 1 and names `list-accounts`. `demo` skips a farm with any flock and fails before writing on a farm with any customer: after a late failure it deletes every flock-rooted row, customer, order and line of the farm (#1081). `simulation` refuses the flag because its manifest, cast emails and pinned counts assume the default farm. The sim harness demo-seeds a second farm for the README dashboard capture. The simulation fixture cannot supply that capture: its ~100 never-filing catalog flocks leave every day partial, so the trend strip has no complete day to scale against. → [`280-seed-and-simulation.md`](../docs/decisions/280-seed-and-simulation.md) · [runbook](../docs/runbooks/simulation-fixture-on-a-dev-database.md) for loading the simulation fixture into a local debug database
- **A write-contract change must update its non-CI callers (#394).** Coverage is uneven and has changed since this rule was written. Seeder tests reach only the handler layer; **validator-only** tightening is invisible to them. `tools/simulation/k6/` remains **uncovered**: `k6-baseline.yml` is `workflow_dispatch` only, and tolerated statuses let a run pass while writes stop landing. **Playwright specs are no longer uncovered**. Since 2026-08-08, `e2e-smoke.yml` runs the quick suite on every `pull_request` touching `src/**`, `web/**`, `tools/simulation/**` or `deploy/**`, which covers every write-contract change. CI catches broken specs there. Docs-only PRs skip it; `slow`/`canary` remain dispatch-only. **Verify the request/status contract by reading callers, not by running them**. Reading still finds the k6 case and reveals changes to a caller's intent. → [`394-write-contract-callers.md`](../docs/decisions/394-write-contract-callers.md)
- **Production logs: compact JSON on stdout; base layer argument-free (#404).** The base `appsettings.json` Console entry contains only `Name`; a template beside the formatter is **silently** bound instead. Trace fields differ by format: `@tr`/`@sp` in compact JSON, `{TraceId}`/`{SpanId}` in the Dev template. Compact JSON serializes **every** property, so anything pushed through `BeginScope`/`LogContext` reaches the collector. → [`404-production-logs.md`](../docs/decisions/404-production-logs.md)

### Deploy invariant: exactly ONE serving API instance (#271)

**Run one serving instance.** Every instance runs `DurableJobWorker`; its poll and three recurring sweeps run **only under a single-leader gate**. This session-scoped Postgres advisory lock, `pg_try_advisory_lock`, uses a dedicated, non-pooled connection (**#271**). At most one instance leads; a dead leader's session releases the lock for automatic crash recovery. The contract is at-most-one-leader with at-least-once, idempotent handlers, never "exactly once". It holds on a **session-pinned** Postgres endpoint, either direct or session-pooled. Under a **transaction-pooling** proxy such as PgBouncer in transaction mode, the lock can migrate across backends; single-leader is *not* guaranteed. A backend-PID affinity check narrows but does not close that window. This topology relies on the at-least-once + idempotent contract, or the operator points `ConnectionStrings:LeaderLease` at a session-pinned endpoint (**#556**). The per-account report concurrency cap (#311), the last independent in-process blocker, now uses the shared renewable lease (#545, #543), keyed by `AccountId`, with each permit pinned to its granting backend. N replicas enforce one combined per-account count; a store outage degrades to a bounded per-instance ceiling, never fail-open. The IP-keyed auth limiters (#143) now use shared `IFixedWindowCounter` (#544, #543), backed by Redis with an in-process fallback + alarm, so N replicas enforce one combined per-IP budget instead of N. The step-up grant registry spans replicas (#338): replay uses shared `IClaimOnceStore` (#543); logout revocation uses durable per-user `ApplicationUser.StepUpLogoutEpoch`, an integer compared for equality, never a timestamp. Both survive across replicas without a shared clock. HTTP write idempotency uses a database-coordinated claim/result protocol across replicas (#307); **this does not license scaling.**

**Do not extend that list from memory**. Two previous derivations missed process-local limiters. Walk every `AddSingleton`/`AddHostedService` under `src/`, every in-memory state primitive, **and registrations inside every package `Add*`/`With*` extension called by `Program.cs`**. `src/` cannot show those internals: one `builder.Services.AddThing()` can register multiple services, including hosted services (#786). Graph the version resolved by `packages.lock.json`: `graphify clone <repo> --branch <tag>`, `graphify update . --no-cluster`, then `graphify explain "<ExtensionName>"` lists registrations with line numbers. Exclude deliberately after walking. As of 2026-08-25, the walk finds **19 `AddSingleton` call sites and 1 `AddHostedService`**. Count call SITES, not live registrations. `SharedStateRegistration.cs` registers `IClaimOnceStore` and `IFixedWindowCounter` twice each on mutually exclusive Redis/fallback branches: at most **17** are live per process, **16** with Redis unconfigured. This count has gone stale twice; re-run the walk, never trust the recorded count. Run-then-exit verbs are unaffected because they never start hosted services. The #543 registrations, `IConnectionMultiplexer` + `IClaimOnceStore`/`IFixedWindowCounter`, are **not** blockers; they provide the shared store. #338 wired the `IClaimOnceStore` grant-replay caller; #544 wired the `IFixedWindowCounter` auth limiters. #545 wired the report cap directly to lease backends. `ReportConcurrencyCapRegistration` constructs `RedisLease`/`InProcessLease` and pins each permit to its granting backend, rather than resolving a shared `ILease` port from DI. Redis-backed implementations are multi-replica-safe; their in-process fallbacks are deliberate, alarmed degradation. → [`271-single-serving-instance.md`](../docs/decisions/271-single-serving-instance.md)
