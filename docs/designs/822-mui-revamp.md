### 2.3 The ten bare element selectors, at six sites

These apply to MUI's DOM whether or not a screen has been converted, and no screen slice deletes them. That is why #823 is more than a `CssBaseline` decision.

```
* (L299)                      box-sizing
body (L303)                   margin background color -webkit-font-smoothing
h1,h2,h3,h4 (L310)            font-weight letter-spacing line-height
button (L317)                 padding border border-radius background color font
                              font-size font-weight letter-spacing cursor transition
label (L433)                  display flex-direction gap font-size font-weight color
input,select,textarea (L442)  padding border border-radius font font-size color background
```

Emotion's generated class beats a bare element selector on specificity, so for these single-element rules every property MUI sets wins already. **That does not hold for the compound forms of the same elements**, which the list above omits and which beat MUI's class: `button:hover:not(:disabled)` (L331, repaints every MUI `Button` to `--brand-press` on hover), `button:active:not(:disabled)` (L335), `input:focus, select:focus, textarea:focus` (L452), `.form-grid label` (L472), and `input[type="checkbox"] { width: 1rem; height: 1rem }` (L458-461), which overrides the full-size hidden `<input>` MUI's `Checkbox`/`Radio`/`Switch` use as their hit target (`internal/SwitchBase.js:81-82`) and would leave every MUI checkbox with a 16px target on a PWA whose own guards enforce 44. So #823 does not work from this hand list. #824 ships a postcss walk that emits every rule whose selector contains a bare element name (`*`, `body`, `h1`-`h4`, `button`, `label`, `input`, `select`, `textarea`, `a`, `table`, `th`, `td`), pseudo-class, pseudo-element and attribute compounds included, and #823 neutralises that emitted list with deliberate exclusions written down. The properties to neutralise are the ones MUI leaves alone, where `styles.css` still applies: for `button`, `letter-spacing: 0.01em` and `transition`; for `label`, `display: flex; flex-direction: column`, `gap` and `color: var(--muted)`, which would otherwise reach the `<label>` MUI's `TextField` and `Autocomplete` render. #823 enumerates them from the list above rather than guessing.

Typography and spacing have no scale today: 78 `font-size` declarations across 25 distinct values, and 320 rem spacing values across 41 distinct steps, of which 106 (33%) land on an 8px multiple.

## 3. Decisions, and the facts behind them

### D1. The conversion rule. A screen is converted when its CSS leaves `styles.css` in the same PR

The #829 lesson, stated as a rule the reviewer can check from the diff: **a screen slice deletes that screen's rule family from `styles.css` (§2.2) in the same PR that introduces MUI on the screen, and the screen's TSX carries no `className` that `styles.css` still declares.** Wrapping markup in `Paper` under a `.panel` that already sets background, border and radius (L1697-1708) is a second opinion under one that already won. The check is mechanical: for each `className="x"` left in the converted file, `grep -n "^\.x\b" src/styles.css` returns nothing, except the four survivors that stay for good (`.sr-only`, `.skip-link`, `.nav-group-label`, `.more-group-label`), the one expiring survivor (`.content` on `<main>`, `AppLayout.tsx:98`, which stays until #833 deletes its six rules, §2.2) and the data marks that are kept (`DayStrip`, `StockBar`, `.meter`, `GradingChip`, `BrandSplash`). Anything else still declared is an unconverted screen with MUI imports, which is the spike.

Three review signals follow. A conversion PR whose `styles.css` diff is empty is not a conversion. The before/after screenshots at 1280 and 390 are the evidence, not the test count; the spike was green on 39 tests while changing nothing. Any `sx` or `styled()` that re-states a property the deleted rule set is a smell: the CSS moved rather than died.

The guard that makes this a fact rather than a review note is G1 (§4). Applied to every screen slice: #829, #830, #831, #832, #833.

**Consequence for the guards.** Ten guards parse `src/styles.css` with postcss and assert over selectors in a stylesheet Emotion never writes to. As a screen's rules are deleted, its selectors stop being rendered, and a guard that keyed on them keeps passing with less under it. Two guards keep their reach through any amount of conversion because they assert over **token values**, not selectors: `styles.test.ts` and `theme/farmTokens.test.ts`. Tokens stay in `styles.css` and reach MUI through the bridge.

The rule for #824: **a guard assertion is retired only in the PR that deletes the rules it walks, and each retired assertion names its successor** (a row in the theme guard G2, a source-shape guard like G1, a component test, a Playwright spec) **or is recorded as a deliberate coverage reduction in that PR's body.** Silent shrinkage is what AGENTS.md's "wrong guard reads as safety" describes, and a retired assertion with a named successor is the opposite. The replacement is chosen per guard by what the guard is about:

- **Theme assertion (Vitest)** for facts that become theme configuration. Cheap, and it is where `farmTokens.test.ts` already lives.
- **Source-shape assertion (Vitest, regex over TSX)** for "this call site must still name this component". `routes/emptyStates.guard.test.ts` is the existence proof: it reads JSX source, not parsed CSS, so it stays sighted through a conversion of the pages around it.
- **Rendered-DOM assertion (Vitest + jsdom)** for which element or role is produced. **Never for computed style**: jsdom loads no stylesheet and the fallback palette diverges on 6 of 17 tokens (§2.6).
- **Playwright** for anything geometric, `inert`, scroll lock, or a computed colour, per #501 and `src/ax.ts`.
